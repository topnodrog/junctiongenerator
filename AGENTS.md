## GitHub handoff is the default

The project owner often forgets to request the final GitHub handoff. When a requested implementation is complete and verified, proactively finish the normal delivery workflow without waiting for a separate request: review the diff, create a focused commit, push the current branch, and open or update the pull request. Do not stop after merely recommending these steps.

Preserve unrelated user changes and never include secrets or incidental files. If the working tree mixes unrelated work, separate only the files that clearly belong to the completed task. Ask before proceeding only when the commit scope is genuinely ambiguous, verification is failing, credentials or permissions block the operation, or the GitHub action would be unusually risky.

## Use Serena selectively

Use Serena only when symbol-level code navigation is materially useful. Do not activate Serena or load its architecture memories for general questions, GitHub operations, documentation-only work, website-only work, or routine file edits. When Serena is useful, load only the specific memory or symbol context needed for the current task; do not load every project memory by default.
