# Outreach plan — a low-friction public funnel for independent review

**Owner decision (2026-11-02):** prioritize a **low-friction public funnel** (GitHub issue templates, reproducible-build challenge, public gate-status snapshot, one-page review pack, short outreach copy) over cold, high-commitment recruiting. Infrastructure: **mixed** owner hardware + independent VPS + community operators, with zero Google Cloud / Fly.io. This pass is **prepare only**; no network was started and no value-bearing launch is claimed.

**Problem with the obvious approach:** emailing auditors asking for a "mainnet security review" converts poorly because (a) there is nothing reproducible to review yet, (b) the request implies a large unpaid commitment, and (c) a zero-value research chain is easy to dismiss as hype. The better funnel is an **evidence-first ladder**: make the first action take ten minutes and produce a public artifact.

---

## 1. The ladder

| Stage | Time to first win | Public action | Artifact produced | Conversion metric |
| --- | --- | --- | --- | --- |
| 1. Discover | 30 seconds | Read the one-pager | — | Unique visitors / stars / issue-template views |
| 2. First win | ~10 min | Reproduce a build or run a node locally | Rebuild attestation issue, or seed in `inventory.json` | # independent rebuilds, # external runners |
| 3. Verify | ~1 hour | Run `gates:status`, `proof:registry`, `infra:guard`; confirm the chain is blocked | Comment / issue with output | # verified environments |
| 4. Contribute | 1 day | File one finding, add a test, or operate one seed for 30 days | Findings-register entry, signed evidence envelope | # findings, # seeds, # evidence records |
| 5. Sign | 1–2 weeks | Publish a version-specific review / rebuild attestation | Signed report + `gate-evidence.json` record | # reviewer keys in `launch-policy.json` |
| 6. Advocate | ongoing | Share the reproducible result, mentor the next operator | Public talk/post, new applicant | Referrals per reviewer |

**Design rule:** never ask for a signature before stage 4. Ask for a *reproduction* first. A person who has already reproduced the build is far more likely to become a reviewer, and the reproduction itself is useful evidence.

## 3. The reproducible-build challenge (the key growth loop)

> **"Reproduce the release. Post two SHA-256 digests. That's it."**

1. Pin a release commit/tag and publish `RELEASE-MANIFEST.json` + `SHA256SUMS.txt`.
2. A participant runs `npm ci && npm run build && npm run release:check` on their own OS/architecture.
3. They open the rebuild issue template with: OS, Node version, commit, `treeSha256`, archive digest, and whether it matched.
4. A mismatch is a **finding**, not a failure — it gets a findings-register entry. A match is an independent rebuild attestation and feeds `reproducibleArtifacts`.
5. Publish a small public leaderboard of *organizations* (not individuals) that reproduced successfully.

Why it works: it is finite, verifiable, needs no permission, has no financial incentive to distort, and produces exactly the evidence the `reproducibleArtifacts` gate needs. It is also the natural first contact for build/security engineers who later become reviewers.

## 4. Channels, in priority order

1. **GitHub-native (zero friction, always on):** pin a "Join the independent review program" issue; add the one-pager to `README.md` and `docs/mainnet/README.md`; put the gate snapshot in release notes; label `review-program`, `rebuild-attestation`, `finding`, `operator`.
2. **Direct, named, low-volume outreach:** 6–10 specific ZK/PQ/privacy researchers, distributed-systems auditors and build engineers. One short email, one clear 10-minute ask, no deck. Template below.
3. **Local and regional (owner is in Cambridge, Ontario):** University of Waterloo, Wilfrid Laurier, University of Guelph, McMaster and U of T security/crypto groups; Toronto/Waterloo privacy and blockchain meetups; a 20-minute "reproduce a chain" workshop. Offering a workshop converts better than asking for a review.
4. **Research communities:** ZK/STARK and post-quantum mailing lists, IACR-adjacent reading groups, audit-firm pro-bono/research slots. Lead with the open cryptographic questions, not the project.
5. **Operator communities:** self-hosting/home-lab and small VPS co-op groups. The ask is "run one seed for 30 days with your own DNS", which is concrete and cheap.
6. **A single Show HN / community post** only after the reproducible bundle and three independent seeds exist — titled around the reproducible challenge, never "mainnet launch".
7. **Quarterly public readiness note:** one page with the gate snapshot, what changed, what is still blocked, and one explicit ask for the next quarter. Predictability builds trust.

Avoid: mass DMs, token-sale language, "mainnet is live", paid-positive reviews, countdowns, and any incentive tied to a clean report.

## 5. Copy you can paste

### 5.1 Public announcement paragraph

> Junction Generator is a zero-value testnet candidate for proof-of-useful-compute. No JGC mainnet exists and JGT is a legacy token we do not sell or promote. We are opening an independent review program: reproduce our release bundle, run a seed on your own hardware/VPS, or review a specific protocol gate. Everything is reproducible, all findings are public, and we have a safe-harbor policy. The ten open mainnet gates and their exact acceptance criteria are published as machine-readable JSON. Start with the 10-minute rebuild challenge.

### 5.2 Direct reviewer email (short)

> Subject: 10-minute reproducible build + one open ZK question (JGC)
>
> Hi <name> — we're a small zero-value research chain, not a token launch. Before asking anyone for a review, we're asking for a reproduction: `npm ci && npm run release:check` on our pinned tag; post the two digests in the issue template. If that is interesting, the open question I'd value your view on is <one specific gate, e.g. the PQ proof backend choice>. No commitment, no payment tied to conclusions, findings are public, safe harbor in SECURITY.md. Links: one-pager, review pack, gate status.

### 5.3 Operator invite

> Bring your own host, DNS and TLS. Run one of three independent seeds (owner hardware + two non-Google/non-Fly VPS or community hosts), publish your `wss://` URL in `inventory.json`, and keep it up for 30 days. `install.sh`, `verify.sh`, `backup.sh` and a dependency-free monitor are in the repo. This is zero-value rehearsal; availability evidence feeds the soak gate. No cloud token or shared credential is needed.

### 5.4 Rebuild challenge post

> Reproduce `jgc-node` at commit <sha>. Post OS, Node version, `treeSha256` and archive SHA-256 using the rebuild issue template. A mismatch is a finding and gets logged publicly. Two independent matches close part of our `reproducibleArtifacts` gate. Takes about ten minutes.

## 6. Metrics and public reporting

Publish a small monthly table in the readiness note — counts only, no personal data:

| Metric | Target before external review |
| --- | --- |
| Independent rebuild attestations | ≥2 (different OS/architecture) |
| Independent seeds with 30-day evidence | ≥2 beyond the owner's seed |
| Verified `gates:status` reproductions | ≥5 |
| Findings filed (any severity) | ≥10, all with reproductions |
| Reviewer keys in `launch-policy.json` | ≥3 from ≥2 organizations |
| Signed gate evidence records | 12 |
| Median time from first contact to first artifact | < 7 days |

Also track the *negative* signal: if the 10-minute first win has <10% completion, the pack is too complicated — fix the pack, not the audience.

## 7. Funding guardrail (owner premine proposal)

The owner proposed premining roughly 3–5 weeks of issuance (151,200–252,000 JGC) to fund reviews and future bounties. This **cannot** fund the funnel today: a premine only has value after the value-bearing network it would help authorize, and paying reviewers in that asset is a conflict of interest. See [`PREMINE_FUNDING_DECISION.md`](PREMINE_FUNDING_DECISION.md).

Default for this funnel: **no-budget fallback** — recognition, public attestations, reproducible artifacts, a workshop, and milestone grants only if separate funds are available. All compensation is for time and evidence quality, never for a clean report. If a sponsor or grant appears, record it publicly before any reviewer is engaged.

## 8. Kill criteria

If after two full outreach cycles there are fewer than two independent reviewers and fewer than two independent seeds, do not rebrand the owner-only network. Keep it a zero-value canary, publish that fact, and keep the gates blocked. The funnel's purpose is evidence, not optics.
